## 1. 产品依据与已经确认的规则

以 Wehos 在 2026-09-08 的两段对话为准：声纹用于激活；待机可以无差别缓存音频，激活时回放；短音频可以不能激活，但激活状态下不再按声纹拦截；激活保持一段时间；能力覆盖独立 ASR 和原生音频对话。优先解决语音会话闲置激活，实际分发、性能和系统环境是首版验证重点。

用户已经确认：**连续 30 秒无人说话后回到待机**。不是激活后固定 30 秒强行结束，也不另加未经确认的连续对话最长时限。

2026-09-09 用户确认以开发状态实测作为本 PR 的环境验收依据。Web 与 Electron 多窗口行为可分别用开发启动验证，无需制作 Electron 发行包；发行目录、Nuitka 和安装包验证留给后续发行工作，未测部分不声明已通过。

本方案中的“声纹档案启用／模型就绪”与“语音对话已激活”必须分开命名和呈现，避免复用旧代码的 activation 一词后混淆配置状态与对话状态。

| 场景 | 必须表现 |
|---|---|
| 麦克风开启，声纹激活功能开启 | 本地收音、有限缓存，等待本人语音 |
| 待机时只说很短的“嗯／好” | 可以无法激活；不拼接下一句、不补静音制造验证时长 |
| 获得有效本人证据 | 激活，回放本次候选开头，再接续实时输入 |
| 已激活，本人说短句 | 不再因为声纹证据不足拦截，继续走正常语音链路 |
| 已激活，旁人说话 | 同样可能进入对话，属于该模式的产品取舍 |
| 连续 30 秒无人说话 | 回到本地待机，下一次对话重新需要激活 |
| 显式关闭声纹激活功能 | 进入普通语音模式；界面明确不再要求声纹激活 |
| 关闭麦克风／结束语音会话 | 停止采集，撤销权限，清空本地缓存并回收工作任务 |

声纹不是唤醒词识别，也不能判断“本人是不是在对猫娘讲话”。不要求口令的前提下，本人对其他人说话也可能激活。声纹不是活体认证；本轮不扩展抗录音重放能力。

## 2. 首版范围与排除项

### 2.1 首版必须完成

1. 通用音频入口的待机／验证／激活／闲置恢复控制。
2. 有界缓存与首次激活音频回放，保证顺序和发送失败语义。
3. 复用 CAM++，评分不依赖 ASR 的文字、utterance ID 或远端起止事件。
4. 独立 ASR 和原生音频两条生产组装路径均接入。
5. 激活模式停用旧的逐句声纹拒绝器。
6. 配置、运行状态、错误和关闭流程在 Web／Electron 一致。
7. 开发环境的模型资产、运行依赖、普通 CPU 资源与进程退出验证；实际发行环境检查留到后续发行工作。
8. 录入音频与实时评分采用一致的处理合同；必要的录入修复不能省略。

### 2.2 本轮不引入

- pVAD、ECAPA、ECAPA2、TSE 或短句校准参数包。
- 每句重新识别身份、连续多人声纹分段、重叠声源提取。
- #2980 的 exact 子回合提升、混合证据粘滞拒绝、拒绝后静音重武装等整套增量。
- 更换 ASR Provider、改动 Core→ASR 的选择规则。
- 把语音激活用作文字输入、游戏命令、图片输入的全局权限系统。
- 未验证平台的“全平台已支持”承诺，或为绕过安全存储限制改用明文档案。

“先上线接受考验”解释为先交付这套范围有限且可回退的能力，实测后继续迭代；不解释为可以跳过录音错投、重复发送和模型无法分发等基本检查。

## 3. 基线与 #2980 复用清单

main 已包含 CAM++、基础档案加密、单段录入服务、统一音频处理、独立 ASR/native 共同分流入口，以及旧版逐句过滤。因此新方案不需要搬入 #2980 的整个语音运行时。

| 模块／能力 | 复用方式 | 依赖边界 |
|---|---|---|
| CAM++ 权重、manifest、特征前端和基础推理 | 优先使用 main | 不带入短输入探测作为激活依据 |
| 声纹档案、安全存储、配置读写 | 在 main 上扩展 | 保留校验和原子保存；明确音频合同版本 |
| 3×3 秒参考＋1×5 秒验证、2 秒准备 | 从 #2980 提取完整功能补丁 | 连同后端 API、前端状态、8 语言和必要测试；不迁辅助模型卡片 |
| 录入与运行时归一化、EOF 尾部结算 | 提取必要修复 | 与取消、异常清理配套；不改变普通实时流的 EOF 语义 |
| 评分进程、串行调度、关闭回收 | 复用已验证机制，做轻量适配 | 不直接复制最新版共享宿主，因为它依赖 pVAD 和扩展 Shadow runtime |
| 会话／档案代次、迟到回调防护 | 复用设计与相关修复 | 为激活状态定义自己的代次，不引入 exact 证据协议 |
| 缓存与发送器 | 复用有界容器和单写者思路 | 现有 700 ms ASR pre-roll 不足以承担激活回放，不能仅调大常量冒充完成 |
| 原逐句声纹过滤 | 本模式不挂载 | main 已有的过滤也必须处理，不能只是不搬 #2980 增量 |

提取方法：先比较功能引入前后的差异，再检查后续修复，制作针对 main 的最小补丁。早期提交只作来源，不能默认它没有后续修复过的缺陷。每个提取补丁都要说明来源、保留行为、丢弃依赖和回归用例。

## 4. 总体架构和依赖方向

```text
麦克风输入与采集身份
  → 统一降噪／AGC／limiter／16 kHz 单声道 PCM
  → 通用语音激活控制
       ├ 待机：本地活动检测＋有限缓存＋CAM++ 候选评分
       └ 激活：有序回放／实时转发，停止身份检查
  → 既有音频路由
       ├ 独立 ASR → 原有断句与文本交付 → Core
       └ 原生音频会话 → Core
```

建议分为三层：

- `main_logic/voice_input/activation/`：配置、状态机、帧缓存、权限代次和输出决策。只依赖中立帧与评分接口，不 import Core、Provider 或应用组装模块。
- `main_logic/voice_identity_service/`：CAM++ 评分适配、档案兼容和资源所有者；模型失败返回明确状态，不替激活控制器决定自动放行。
- `main_logic/core/asr_runtime.py` 与 `app/main_server/voice_identity_runtime.py`：组装、接线、配置同步和生命周期。Core 不承载声纹策略算法。

评分接口只接收 PCM、采样率、档案／模型代次和候选身份，返回有效分数或分类失败；不接收 transcript、ASR utterance 或 Provider exact proof。

本地活动检测负责候选起音和闲置时间；远端 VAD／SmartTurn 保留自己的断句职责。两者可以各有独立流状态，不共享会被不同调用者 reset 的同一个可变实例。

## 5. 状态机与闲置规则

| 状态 | 音频处理 | 退出条件 |
|---|---|---|
| DISABLED | 普通语音路径，不缓存待激活音频 | 用户启用功能 |
| PREPARING | 本地有界缓存；尚无对话授权 | 模型和档案可用，或准备失败 |
| WAITING | 本地活动检测与缓存，未向对话 Provider 发送麦克风 PCM | 候选达到评分条件 |
| VERIFYING | 推理在后台进行，采集继续，缓存有界 | 本人证据成立／不成立／失败／失效 |
| REPLAYING | 唯一发送者先排空选定缓存，再衔接实时输入 | 队列追平，或发送失败 |
| ACTIVE | 正常转发；不进行逐句声纹过滤 | 连续 30 秒无人说话／权限撤销 |
| UNAVAILABLE | 显示原因；功能开启时不自动放行待机音频 | 用户重试、修复条件或显式关闭功能 |
| CLOSED | 不采集、不发送、清除本代缓存和任务 | 新建麦克风会话 |

### 5.1 30 秒规则

- 基于本地有效人声活动和单调时钟计时，不基于 ASR final 到达时间。
- 激活期间的任意有效人声都可以更新闲置时间；因为此时不再验身份，不能宣称“只有本人可以续期”。
- 新的人声在 30 秒截止前实际采集到，允许续期；截止之后开始的声音需要重新激活。按采集顺序处理截止附近的帧，不按后台任务完成顺序猜测。
- 回放旧缓存不能把它当成新的人声反复续期。帧保留原始采集时间与序号。
- 不能因为每帧都有 PCM／背景噪声，或者 TTS 正在播放，就自动续期。
- 自身播放回声被麦克风误识别为人声的风险必须实测；仅靠播放状态不能证明回声已消除，也不能简单在 TTS 期间禁麦导致无法插话。
- 到期只影响之后的新输入；已发送且仍在等待 final／回复的旧回合按原合同完成，不删除历史，不重投音频。
- 不引入额外的固定最长激活时间。持续有人讲话时可以持续 ACTIVE，但资源必须保持有界。

### 5.2 与 Provider 会话的关系

待机不是关麦，也不要求所有 Provider WebSocket 永久保持连接。可复用现有连接预热能力；连接已超时就按原协议重建，在准备完成前继续有界缓存并显示状态。

不得用假人声或循环静音保活规避 Provider 的空闲限制。也不承诺待机无连接费或零远端成本；本方案只约束待机麦克风 PCM 不进入对话 Provider。

## 6. 缓存、回放与发送约束

### 6.1 缓存范围

无差别缓存指采集时不先按说话人丢帧；不等于激活后把全部历史缓存上传。回放选取当前候选语句及有限前导上下文，避免补送几秒前另一人的完整发言。

此处候选由活动与停顿界定，不是已经实现说话人分离。同一连续候选内先旁人后本人、或两人重叠，回放仍可能包含旁人；首版明确保留这一限制，不伪造逐帧 Owner 证明。

建议初始工程参数如下，均是待测参数，不是已验收结果：

| 参数 | 初始建议 | 说明 |
|---|---|---|
| 环形音频缓存 | 8 秒／256,000 字节 PCM16 | 16 kHz 单声道；另计帧元数据和评分快照 |
| 候选前导上下文 | 约 300 ms | 通过首字完整性实测调整 |
| 候选评分时间 | 优先复用 1.5 秒和 3 秒长输入条件 | 满足语音质量条件；不以静音凑长度 |
| 同时在途评分 | 1 个 | 不因每帧到达创建推理任务 |
| 等待评分队列 | 至多 1 个候选 | 旧候选失效／结束后有序接续，不无限积压 |
| 单候选缓存覆盖 | 必须完整处于缓存内 | 开头被淘汰后不拿不完整片段冒充完整激活语句 |

最终缓存、候选和评分字节数同时设硬上限；候选快照数量不随会话长度增长。

### 6.2 回放必须满足

1. 每帧绑定采集序号、采样范围、采集时刻、路由／会话／麦克风代次。
2. 激活时固定回放截止序号；此后新帧排在回放之后，由同一个发送者处理。
3. 不重新做一次降噪或重采样；使用已经归一化的缓存帧，保留来源身份。
4. 每帧至多交给下游一次；回放不能再进入自己的待机缓存或再次触发激活。
5. 新模块与既有 ASR pre-roll／hot-swap 缓存分别记录“已提交”范围，禁止重复补头。
6. Provider 能否加速接收积压音频、最大帧尺寸、接续延迟必须按实际适配器验证。不得默认所有实时接口支持瞬时灌入数秒音频。
7. 回放无法追平、队列溢出或时间线断裂时，停止本次交付并显式失败，不能悄悄丢中间帧。

### 6.3 部分发送失败

严格区分未发送、已写 transport、Provider 已确认、已进入历史。只有能证明未发送的帧才允许继续原操作。已写入或发送结果不明时不自动整体重放；必要时按适配器合同结束不安全会话，提示重试。

关闭功能时丢弃待机缓存，不能因用户取消声纹功能突然补送之前一直未授权上传的录音。

## 7. 评分、档案和失败语义

- 首版继续使用 CAM++，不通过更换模型解决激活状态机问题。
- 1.5 秒是现有标准输入的工程起点，不是身份可靠性的数学界线。短句不能激活是允许的；长句也可能误拒或误激活，需要分别记录。
- 旧 `0.40` 只可作为初始试验阈值。旧系统的“两次低分拒绝、其余放行”不能直接改名为“本人确认”；新策略需要明确的正向激活条件，并验证整个待机会话的误激活率。
- 初版可在有限的 1.5／3 秒候选上评估明确正向分数，不无限滑窗反复抽奖。最终阈值与重试步长在开发样本上冻结，再用独立录音验收。
- 待机遇到短句、不足、低分、NaN、档案错配、超时或模型失败均不激活；失败原因与普通“尚未确认本人”分开显示。
- ACTIVE 时不再运行身份评分。评分器发生故障不应凭空追溯拒绝已经激活的语音；到期重新激活时才要求评分能力恢复。输入／传输故障仍由既有语音链路处理。
- 档案被删除、替换、显式禁用或麦克风权限撤销时立即撤销对应激活权限；不能把旧档案的授权留给新档案。
- 复用 3+1 录入时，音频处理、特征模型、参考形成方式和档案版本一并绑定。兼容性无法证明的旧档案提示重新录入，不直接把不同处理域的向量混用。
- #2980 的辅助参考和新版档案不能无条件移入 main；首版只声明经过检查的 CAM++ 档案兼容范围。实验分支测试使用隔离状态目录，避免把用户正在使用的档案重写为另一套 schema。

## 8. 生命周期、并发和资源所有权

评分／回放任务捕获麦克风代次、输入所有者、路由／会话代次、档案／模型代次、候选编号和权限修订号。任何 await 后，在激活、发送、发布状态或清理前重新检查。

| 事件 | 必须动作 |
|---|---|
| 关闭麦克风／结束会话 | 先封住新产出，再取消与回收；清空缓存和权限 |
| 路由切换／重连 | 旧回放不转投新会话，旧评分不授权新路由；首版保守重新激活 |
| 开始录入／更换档案 | 撤销旧权限，等待旧评分退出，新档案成功后重新待机 |
| 切换输入所有者 | 防止聊天缓存进入游戏或另一角色；未支持路径显示明确状态 |
| 取消／推理超时 | 回收底层进程或保留被隔离的退休所有者，不能只取消等待 |
| 旧任务迟到 | 只清理自己持有的资源，不能关闭接管者或发布 ACTIVE |
| 关闭后重开 | 新代次、新权限；不使用上次缓存和验证结果 |

资源方案优先复用已有的可终止工作进程机制。一个实际采集入口只保持一个评分工作者；禁止每次尝试激活启动一个新进程、禁止 Web 与 Electron 同时重复评分同一输入。

模型加载、推理、文件校验与关闭不在音频事件循环中同步执行。评分队列单飞；关闭不能因底层永久阻塞而不断创建后继进程。模块所有者明确负责进程、管道、数组、定时器和回调的最终回收。

## 9. UI、配置和隐私

设置名称建议“声纹激活语音对话”，说明：“确认是你后开始对话；对话期间可直接接话，连续 30 秒无人说话后重新等待激活。”另说明“激活期间也会接收附近其他人的声音”。

运行状态至少区分：功能关闭、准备中、等待你说话、已激活、暂时不可用。不能把“模型已安装”显示为“对话已激活”。录入页面继续显示档案状态；会话状态通过带代次的事件更新，不用高频全局刷新。

声纹功能偏好与运行时 ACTIVE 状态分开存储；ACTIVE 不跨进程重启、角色切换或麦克风会话持久化。30 秒暂作默认内部配置，首版不必增加复杂调参界面。

提取四段录入时，浏览器和 Electron 均保留准备、录制、验证、取消、关闭页面释放等状态。所有新增文案同步 8 个 locale。

Core 的 `_capture_voice_session_activation_generation` 将 `id(self.session)` 纳入身份；正常 promote 更换 session 后，下一次麦克风路由会退休旧激活运行时并创建 PREPARING 运行时。相同 Provider 的 reconcile 本可保留独立 ASR 与麦克风路由，这并不意味着用户结束了语音对话。因此本次重新待机不能作为“连续 30 秒无人说话”验收通过的证据。

**已用生产控制器隔离验证的交接边界：**

- 激活资格的最后人声结束于 0.3 秒，截止为 30.3 秒。对同一份 30.2 秒采集的人声，先 ingest 再在 31 秒 tick 会保持 ACTIVE；先在 31 秒 tick、再 ingest 该缓存帧则保持 WAITING。证据说明保留时间戳本身不够，必须协调计时器与尚未消费的采集事件。该探针不代表实机已经发生这次时间边界竞态。
- ACTIVE 仍可有已领取、尚未确定发送结果的输出帧；关闭控制器会清空这些待发送帧。不能通过单独检查 ACTIVE 或复制布尔值就认定音频已经完成交付。
- 在途发送返回 UNKNOWN 会使控制器进入 UNAVAILABLE。因此不能在切换开始时保存一份 ACTIVE 快照，随后无视发送失败，在新连接上恢复这份旧资格。
- 正常换连接的缓存位于 `_route_microphone_audio` 之前，切换期间的人声可能还没有进入激活控制器；旧运行时的一秒 tick 任务仍会推进时间。这是交接需要覆盖的实际入口关系。

**实施必须遵守的约束：**

1. 区分用户语音会话与后台连接。仅由正常热切换操作显式申请一次性交接，核验旧／新连接、操作身份、麦克风会话、输入所有者、权限代次、档案及音频处理／路由合同。即使最终开关值相同，切换期间发生过关闭再开启，也不得恢复旧资格。
2. 交接开始后阻止旧连接领取新的发送任务；对已有发送做有界收尾。只有交付结果明确、权限仍有效时才能确认继承；UNKNOWN、取消、超时或旧回合归属不明不能伪装无缝成功。已经提交的音频不重投；仍未发送的音频必须保留顺序及原始采集信息。
3. 本地人声活动与计时必须在切换期间保持一致。截止前已采集但尚未处理的帧，必须先完成顺序判定，不能先按处理时刻撤销资格；截止后的新声音也不能追溯激活已经结束的资格。不得简单重置或暂停 30 秒时钟来掩盖排序问题。队列有界，不能因等待丢失的采集事件永久保活。
4. 交接提交前重新检查所有权与最终状态，只继承仍有效的激活资格及原截止时间。WAITING、VERIFYING、REPLAYING、UNAVAILABLE 均不能直接提升为 ACTIVE；尚未完成的验证／回放要明确保持待验证或失败语义。旧回调、旧发送结果、旧清理及旧计时器不能修改接管者。
5. 待机缓存不是已经授权发送的音频。即使交接资格有效，也要按逐帧采集顺序和截止时间判定，不能一概冲刷旧缓存。8 秒／256,000 字节上限、单写者和不重复补头合同保持有效。
6. 停麦、结束语音会话、换角色／档案、权限撤销、输入所有者或音频路由合同变化，按原合同退休资格。普通异常断线不套用正常换连接交接。已有明确分类的 `API_IDLE_TIMEOUT` 原地受控重连保持原合同，不能误删该特例。
7. 本次工作不调整 10 次输入的归档阈值、声纹分数或 1.5／3 秒检查点，不把独立的 TTS 旧会话清理竞态混入此交接修复。

**交接修复的验收条件（当前均不能宣称已完成）：**

| 场景 | 必须证明的行为 |

**Core 路径补充验证与修改范围：**

生产 `AsrRuntimeMixin` 与真实 `VoiceSessionActivationRuntime` 组成的隔离探针覆盖 native／independent 各两种时序：输出已收尾、输出 await 尚未返回。评分结果与 Provider I/O 使用测试替身；不代表真实识别准确率或网络交付验收。四组均先完成 15 帧激活回放，再只替换 Core session 并执行相同 Provider 的 reconcile；麦克风 ingress token 完全相同，激活 generation 仅 `session_id` 改变。随后一帧短输入均触发新运行时 WAITING，旧 scorer 关闭，下游不收到该短输入。在途发送的两组还确认，发送返回时 generation 已变会令旧运行时 UNAVAILABLE，即使独立 ASR 的替身已经返回 ACCEPTED。这证明需要协调实际发送完成与 promote，而不是仅延后界面状态更新。

## 15. 正常自动换连接：详细修复方案与约束边界

状态：**方案已整理，交接修复尚未实施。** 本节将第 14.6 节的证据落实为实施合同；后续实现与验收以本节和主方案的共同约束为准。标注为拟新增的接口名称可随代码风格调整，但其身份、所有权、时序和失败语义不得省略。

### 15.1 修复目标与工作基线

用户开启同一次语音对话后，本人长语音完成激活；后台为整理记忆而自动更换模型连接时，仍保留有效的激活资格。切换后短句继续进入普通对话链路；连续 30 秒无有效人声后才重新等待本人激活。换连接不得延长这 30 秒，也不得把本已过期的资格恢复。

- 在现有 `codex/voice-session-activation` 分支、当前工作区实施，不新建分支或工作树。
- 以当前代码和已完成的降噪／候选容量修复为基础；保留现有未提交改动和诊断证据，实施前逐项区分已有改动与本次新增改动。
- 本次文档编写不代表已经实施、提交、推送或完成实机验收。后续提交仍只包含本任务拥有的改动。
- 所有运行时验证使用开发态；覆盖 Web 与 Electron 开发态，不要求 Electron 安装包，也不要求用户重新提供一批声纹录音。

### 15.2 产品行为与继承边界

| 情况 | 期望行为 |
|---|---|
| 同一语音会话、权限及音频合同未变，正常自动换连接 | 延续当前激活资格和本地人声时间线；实际发送目标受控切到新连接 |
| 切换前已经安静 20 秒，切换耗时 2 秒且没有新的人声 | 完成后剩余约 8 秒，不恢复为 30 秒 |
| 截止前已接收到人声，但它在处理队列中 | 先按该帧的原单调时刻判定；不能因处理晚到而误失效 |
| 截止后才开始新的人声 | 回到待机规则，短句不能借交接自动激活 |
| 激活期间附近其他人讲话 | 仍按第一版规则接收并可续期，不新增逐句声纹拦截 |
| 用户停麦、结束语音、换角色／声纹档案、撤销权限或转交输入所有者 | 立即退休原资格；交接任务不得把它恢复 |
| 麦克风会话、ASR 路由或音频处理合同发生变化 | 走现有退休／准备流程，不当成纯后台换连接继承 |
| 普通网络失败、强制重连、进程重启 | 不套用正常交接许可，保持原恢复边界 |
| 已分类的 native `API_IDLE_TIMEOUT` | 保留现有原地受控重连特例，不与正常连接替换混用 |
| 声纹功能关闭 | 保持原普通音频路径，不新增激活门或搬运原待机缓存 |

本次不调整记忆归档的 10 次输入阈值，不更换 CAM++、不调整 0.40 阈值和 1.5／3 秒检查点，不引入 pVAD、ECAPA、校准参数包或第二套声纹模型。独立的 TTS 旧会话清理竞态另案处理；本修复须验证没有带来新的 TTS 生命周期变化，但不宣称解决了该竞态。

### 15.3 核心设计：把语音资格与传输连接分开管理

采用“**本地语音资格持续存在，后台传输目标显式交接**”。正常切换不重建整套本地声纹控制器，也不把 ACTIVE 私有字段复制到一个新对象。

拟拆出两类身份，保留原 generation 所覆盖的全部撤销条件：

| 身份 | 内容与用途 | 正常换连接时 |
|---|---|---|
| 语音资格身份 | 用户语音会话代次、前端输入连接／租约代次、麦克风代次、输入所有者、声纹档案／策略／权限代次、音频管线及 ASR 路由合同 | 保持不变；仅在上表允许的同一语音会话中延续 |
| 传输身份 | 当前 native Core session 或独立 ASR 接收端身份、路由／操作代次、本次交接编号、发送者代次 | 正常交接时更新；每次实际发送前后校验 |

具体要求：

1. 语音会话代次必须由 start/end、权限和输入生命周期显式维护，不能只比较“角色名、开关值仍相同”。关闭再开启后的同值状态属于新代次。
2. Core session 对象身份仍保留在应受它约束的传输、模型回合及回调检查中。修改 `_capture_voice_session_activation_generation` 前必须逐个分类它的直接调用方，不能简单删除 `id(self.session)` 后让全部旧任务继续通过。
3. 同一资格身份下保留控制器、采集序号、最后有效人声时间和健康 scorer。正常 ACTIVE 交接不重新加载模型、不新增本人评分、不重复创建 idle timer。
4. 本地评分与计时归属于语音资格，后台发送和 Provider listener 归属于传输连接。第 14.6 节中的“旧任务”按其实际所属身份判断：仍由同一语音资格持有的本地任务可以继续；被撤销资格的结果、旧传输任务和旧清理回调必须作废。
5. 每个发送者只持有一次领取的输出与明确传输身份，不得在 await 返回后读取新的 `self.session` 并把原操作冒充成新操作。迟到结果只结算原领取项，不能推进接管者队列。
6. 使用不透明、一次性的交接票据，包含源／目标传输身份、语音资格身份、操作编号、采集／发送边界和操作截止时间。票据不能写入用户配置或跨进程复用，重复提交、被更新操作取代、身份不符均拒绝。

正常换连接后若仅因为控制器重新创建而必须等待模型准备，视为未达到此方案的正常路径验收要求。

### 15.4 音频入口与 30 秒计时的调整

当前热切换会先缓存音频，稍后才交给声纹控制器；本修复需让“本地资格判定”在等待下游连接期间仍持续工作。

目标顺序：

```text
麦克风入口：登记序号、原始接收单调时刻及权限身份
  → 现有归一化／降噪
  → 按采集顺序进入本地激活控制器，更新人声活动与资格
  → 待机：保留有界本地候选，不发给对话 Provider
  → 已授权：进入单一有界输出队列
  → 传输交接屏障
  → 当前 native 或 independent ASR 接收端
```

- 声纹模式下，热切换屏障阻止下游发送，不能阻止本地人声判定。旧 hot-swap 缓存与激活输出队列不得对同一帧各自拥有一份“待发送权”；采用一处拥有 PCM、另一处仅记录操作边界的方式接合。
- 复用现有采集序号与 pending-sequence 机制，并记录尚未处理入口的原单调时刻。idle tick 在宣布到期前，先确认截止前已登记的输入已经按序判定。不能只依赖 tick 的墙钟或让它抢在已有输入之前清空资格。
- 顺序保证须覆盖 raw queue、DSP await、待处理帧和交接输出队列，而不只覆盖最终 flush。已登记的帧必须有“完成／明确丢弃并使当前输入失效”的终态，异常不能遗留永远未完成的序号。
- 待处理输入卡住时，受既有缓冲容量及处理超时约束；输出继续受门控。超过约束则明确失败，不能通过挂起 idle 判定无限保留资格。
- 有效人声按原帧时刻续期；背景 PCM、网络活动、模型回复、TTS 播放状态、评分完成时刻和补发缓存均不能单独续期。
- idle 到期只撤销之后新输入的激活资格。到期前已授权且仍排队的完整输入，按照原交付合同继续完成；不能因进入 WAITING 就删除它，也不能给到期后新声音继承其资格。
- 原样保留采集时间、序号与 PCM 内容。只更新输出项的目标传输绑定，不篡改来源身份，不重新降噪、拼接或伪造为新采集音频。

### 15.5 交接步骤与提交点

后台预热可以继续运行；“需要换连接”与“停止旧发送者领取新帧”必须是两个不同阶段，不能一开始准备就长时间堵住本地采音。

| 阶段 | 操作与必须成立的条件 |
|---|---|
| A. 后台准备 | 保留现有归档和预热流程；旧对话照常运行。准备失败仅清理本次 pending 资源 |
| B. 申请交接 | 确认属于正常切换，核对语音资格和源／目标身份，并确认该路径可以进入安全的输入交接边界 |
| C. 暂停旧发送领取 | 创建一次性票据并关闭旧发送领取入口；本地判定、计时及有界排队继续。仅允许已领取项收尾 |
| D. 结算已有交付 | 等待在途发送结果，结合路径的回合边界判断是否可以关闭旧连接。重新核验权限，不能采用 B 阶段的一份陈旧 ACTIVE 快照 |
| E. 提交连接替换 | 在现有 Core swap／promote 所有权保护下执行旧 listener 收尾和连接替换。每个 await 后检查票据仍当前；成功提交前最后一次确认源／目标和资格 |
| F. 绑定新发送者 | 新连接及路由真正就绪后发布新传输身份，保持本地资格与计时；按原序号发送尚未交付的授权输入。新输入排在已有积压之后 |
| G. 收尾 | 一次性消费票据，清理本次旧连接资源和暂存元数据。状态通知反映最终资格；晚到的旧回调不能清理新资源 |

需要新增或等价实现的中立能力包括：暂停／恢复输出领取、查询在途输出状态、读取资格与人声截止快照、校验采集处理边界。Core 负责 Provider 对象与交接票据，中立控制器不 import Core 或具体 Provider。

**并发和锁约束：**

- 单个 manager 同时最多一个交接操作、一个有效输出领取者；重复申请合并或明确拒绝，不叠加多个暂停／恢复任务。
- 控制器锁仅用于同步状态转换与领取／结算；不得持锁等待网络、scorer、listener、ASR final 或另一把长时间锁。
- 不在持有 Core swap lock 时等待一个仍需获取该锁才能完成的发送／重连／final 任务。先建立停止新领取的操作门，再在锁外有界等待已有工作；提交前重新验证所有权。
- 停麦、权限撤销和 end_session 的同步撤销优先，不等待交接结束。所有恢复操作都需要匹配完整代次，不能只看布尔开关。
- 建议复用现有 5 秒 Core 交接等待上限和 1 秒激活任务关闭上限；一次实际交接从 C 阶段起共享一个单调总截止时间，默认 5 秒。各子等待使用剩余时间，不能串联成多个完整 5 秒。此前后台预热继续使用其原有上限。
- 超时只结束本次交接尝试；不得隐式给语音资格延时。清理走原有有界回收合同，不能留下未被追踪的旧任务。

### 15.6 native 与独立 ASR 的不同交接边界

**native：**

PCM 直接进入旧模型连接，传输写入完成不代表整句话已被处理。若某句前半段已进入旧连接，不能把后半段直接接到新连接上。交接准入应结合本地人声／输入边界和该适配器已有的回合提交、响应归属事件，确认没有尚归属旧连接的未完成输入。

检测到已开始的旧输入时，先让旧回合按原协议完成，再在安全边界进行正常替换；本次尝试不能通过关掉旧连接、清音频缓存或重投前半句来制造“完成”。无法证明边界时应延后该次正常交接，释放实际发送屏障，旧会话保持可用；失败／不可用的旧连接转原异常恢复路径。重试由明确的输入／回合完成事件触发，不高频轮询，不无限积累 pending 连接。

不能假设所有 Provider 都产生相同的 `speech_stopped` 或 `input_audio_buffer.committed` 事件。实现时分别核对现有 server-VAD 与无 server-VAD 适配合同，并通过现有中立边界暴露可交接状态；若某个当前支持路径缺乏可靠事件，须补齐对应适配与测试，不能以永久禁止该路径热切换作为完成。

**independent ASR：**

同一 ASR 接收端和音频合同未变时，Core 模型连接替换不应关闭独立 ASR、清空识别缓冲或重做已接受的 PCM。ASR final 继续由已有 Core voice swap lock 与回合身份保护，保证一次投递给有权接收它的模型会话。交接期间的短暂输出屏障仅用于协调所有权，不改变独立 ASR 的回合状态。

`AsrSubmitStatus.ACCEPTED` 表示该接收层已接受；不能把它宣称为远端识别成功。源 ASR 接收端仍相同时，不因无关的 Core session 身份变化把确定的 ASR 接收结果升级为 UNKNOWN。ASR 接收端、路由、输入代次变化时仍按原有失效语义处理。

### 15.7 各声纹状态在交接中的行为

| 交接时状态 | 处理 |
|---|---|
| ACTIVE | 同一资格持续有效；idle 正常推进。交接期间也可能自然到期为 WAITING，不能恢复旧快照 |
| WAITING | 保持本地待机，候选可在原身份和容量约束内继续积累；不因新连接 ready 放行 |
| VERIFYING | 不因交接直接 ACTIVE。只有仍属于同一语音资格、同一有效候选／请求的真实 OWNER 结果，才按原流程进入 REPLAYING；权限或候选已变的结果丢弃 |
| REPLAYING | 仍必须完成原有一次性回放条件才进入 ACTIVE。部分回放已经进入 native 旧连接时，按上一节推迟切换；不能只迁移剩余半句。独立 ASR 接收端未变时继续原一次性交付 |
| PREPARING | 保持模型准备语义；新连接 ready 不代表本地模型 ready |
| UNAVAILABLE | 不继承成 ACTIVE；按原故障恢复流程处理 |
| DISABLED／CLOSED | 不创建声纹交接资格；普通路径或会话关闭逻辑继续拥有入口 |

### 15.8 失败、取消与回滚

| 发生位置／结果 | 处理 |
|---|---|
| 旧连接关闭前，pending 无效或无法进入安全输入边界 | 撤销本次票据；仅在源连接与资格仍当前时恢复原发送领取，原队列不重投已交付项 |
| 在途项确认 NOT_SENT | 保留原输出项及顺序，允许在合法目标上继续原交付；不复制整段候选重放 |
| 在途项 TRANSPORT_WRITTEN／PROVIDER_CONFIRMED | 记录该层完成，绝不重新发送该帧；native 仍须检查它所属整句的边界 |
| 在途结果 UNKNOWN、取消或超过时限无法确定 | 不恢复陈旧 ACTIVE、不自动重投不确定音频；退休不安全交付并发布可识别的失败状态 |
| 旧连接已关闭，新连接安装或就绪失败 | 不能假装回滚到旧连接；撤销本次交接，沿原连接恢复流程重建，本次不继承资格 |
| 用户在任意 await 期间停麦／关闭功能／结束会话／换档案 | 立即撤销资格、丢弃尚未授权的待机缓存；旧任务只清理自己持有的对象，不能操作接管者 |
| 输出满、采集序号缺口、回放无法追平 | 按原整句交付失败合同处理，不能只扔中间帧继续显示成功 |

对于已发送并仍等待 ASR final／模型回复的旧回合，按现有所有权合同收尾，不删除历史、不为了让界面恢复而重复触发 response 或重启 TTS worker。

### 15.9 容量、性能与可观测性

- 不新增模型文件、网络下载或 GPU 依赖。正常 ACTIVE 交接不新增 scorer 推理或模型进程，也不改变现有评分并发上限。
- 现有待机缓存、输出队列各自的 8 秒／256,000 字节上限继续有效；不是宣称整个语音链路总共只用 256 KB。交接持有原 PCM 引用和少量身份元数据，不再复制一份完整音频缓存；实现时分别统计队列及进程内存。
- 单个交接票据、单个 pending 连接、单写者及原有单评分任务限制必须有行为断言。反复切换后资源数量回到稳定基线，关闭语音后相关任务和进程可回收。
- 增加结构化诊断：交接编号、触发原因、源／目标连接代次、资格状态、剩余闲置时间、积压帧数、是否发生等待／拒绝／失败及原因。不得记录 PCM、声纹向量或原始用户对话。
- 将旧 `Uptime threshold met` 改为准确的触发原因和轮数／token 判定结果，日志文案修正不改变触发策略。
- 正常交接不向界面发布虚假的 PREPARING／WAITING。资格确实到期则发布 WAITING；连接失败使用真实连接状态。状态 revision 保持单调，前端不得通过延时或本地猜测恢复 ACTIVE。
- 只有新增用户可见文案时才同步 8 个 locale；不新增录入界面模块、配置开关或复杂状态面板。

#### 待机首句：连接恢复竞态的隔离复现

后续探针将真实声纹控制器／回放运行时接入 Core 与真实 Silero 检测，评分器固定返回本人，使用本地约 2.52 秒录音（80,554 字节 PCM），ASR 连接及接收端仍为模拟对象。分别测试已有 ready 连接、连接延迟 0.5 秒和 2 秒；等待连接任务真正结束后，三组音频均逐字节完整交付。因此不能把观察窗口内未收到音频直接判为丢失。

同时复现了一项连接恢复竞态：`_handle_transport_prewarm_event` 直接调用 `_restart_transport`，随后 PCM 提交调用 `_ensure_transport_restart_task` 设置另一任务。前者连接期间捕获的运行身份只发生 `transport_task` 变化，就被 `_runtime_identity_matches` 拒绝，已连接候选被关闭；后者取得锁后再次连接。0.5 秒连接配置出现 2 次 connect／1 次候选 close，约 1.14 秒开始交付；2 秒连接配置约 4.13 秒才开始交付。声纹已经 ACTIVE、声纹输出队列为空时，ASR 仍可处于 PREWARMING，首句在下游等待。

关闭声纹的对照也出现 2 次 connect／1 次候选 close，说明这条竞态属于独立 ASR 恢复流程，并非只有声纹回放才会发生。此处已确认的是额外重连和首句延迟；尚无现场逐句发送证据证明用户所述那一次一定由它触发，更不能将其等同于“缓存永远不回放”。下一步修复方向是让预热与 PCM 入口共享同一建连任务，同时保留停麦、换路由、关闭会话的身份隔离，不能简单删除通用身份检查。当前仅新增隔离诊断及记录，未修改生产逻辑。

#### 首句丢失：持续静音挤占待连接缓冲（进一步复现）

上一探针说完即停止喂音频，未覆盖真实麦克风继续采集静音的行为。后续按音频时长持续输入约 2.52 秒本人录音，再输入 12 秒零值静音，最后重说同一句。保留真实声纹控制器／回放、Core、独立 ASR 生命周期、Silero 及发送队列；评分固定为本人，RNNoise 概率为测试输入，每次建连生成独立模拟接收端，无实际网络识别。并行隔离三组连接延迟后得到：

| 单次模拟建连耗时 | 建连／关闭候选次数 | 首次交付时间（从测试开始） | 第一段录音交付 | 第二次同句交付 |
|---|---|---|---|---|
| 0.1 秒 | 2／1 | 约 2.09 秒 | 80,554 字节整段保留；缓冲溢出 0 次 | 逐字节完整 |
| 4 秒 | 2／1 | 约 9.88 秒 | 前缀丢失；录音非零字节由 43,240 减为 16,500；溢出 13 次 | 逐字节完整 |

三组声纹最终均为 ACTIVE。代码原因是 `VoiceInputLifecycleController.accept_audio` 在 PREWARMING／BACKOFF 中把持续到来的音频（包括句尾静音）加入 8 秒 `_pending_connect` 环形缓冲；超容量时淘汰旧数据，仅累计 `buffer_overflow_count`，继续返回 BUFFER。独立 ASR 将 BUFFER 映射为 ACCEPTED，声纹端因此能记录 replay_complete；稍后连接就绪时只发送缓冲中剩余内容。重复建连放大了等待时间，但即使消除重复建连，真正较慢的连接也仍须面对缓冲容量边界。

该实验已复现“首句能激活但没有可识别音频交付，第二句完整通过”的本地机制，不能再将风险仅归为延迟。它尚不能证明用户现场那次的实际连接耗时及溢出情况。修复需同时处理共用建连任务和已接受首句的有界交付：不能让后续静音无提示地覆盖已接受语音，也不能靠无限扩容、盲目重放或删除会话身份检查解决。真实 Provider 的识别结果仍属于后续实测范围；本轮没有修改生产逻辑。

### 15.15 首句回放问题：结论与修复边界复核（2026-09-09）

本节完成的是原因机制和修复约束的分析，不是修复实施或产品验收。沿用当前工作区，未改生产音频逻辑、未重启服务、未提交推送。以下结论优先于 15.14 中较早阶段的“仅延迟”判断。

#### 因果对照与证据边界

在上一实验相同的音频、持续静音、评分替身和独立模拟接收端下，额外改变任务调度顺序：在预热事件入队前先建立受管理的 transport task，使两入口读取同一任务身份。此为隔离探针中的调度对照，不是已落地的修复。

| 对照 | 实际连接次数 | 首次交付时间 | 首句结果 | 第二句结果 |
|---|---|---|---|---|
| 单次连接 5 秒，原调度 | 2 | 约 11.80 秒 | 原始录音非零字节全部丢失，交付仅静音 | 完整 |
| 单次连接 5 秒，先建立受管理任务 | 1 | 约 6.80 秒 | 80,554 字节原始录音完整包含在输出中，溢出 0 次 | 完整 |
| 单次连接 9 秒，先建立受管理任务 | 1 | 约 10.80 秒 | 首句前缀仍丢失，原始 43,240 个非零字节只剩 1,170 个，溢出 22 次 | 完整 |

由此分别确认：重复建连能造成额外等待并触发丢音；待连接缓冲淘汰是另一项独立风险，修复重复建连不能单独消除它。等待时间不是固定必现的 4／5 秒门槛，实际还取决于激活时已有缓存量、后续音频长度、重试和调度。此处按真实时长输入的是规范化 PCM，不是从 Electron 麦克风端到云端的实测。

| 结论 | 当前证据与允许的表述 |
|---|---|
| 麦克风开启后，静音也可继续进入后端 | `static/audio-processor.js` 按帧输出；`app-audio-capture.js` 的上传门控不按音量剔除帧；后端 AudioProcessor／VoiceInputAudioPipeline 不将全部静音自动丢弃。前提是录音、路由权限和 WebSocket 仍有效。 |
| 已交出声纹缓存，不等于识别服务已收音 | 独立 ASR 的 BUFFER 返回 ACCEPTED；Core 将其映射为 TRANSPORT_WRITTEN。现有 replay_complete 只能证明该层已接受，不证明实际 WebSocket 写入、Provider 确认或出字。 |
| 首句可在下游丢失，第二句可以正常通过 | 已由持续静音实验复现；因此不能以第二句成功或 ACTIVE 状态证明第一句完整。 |
| 声纹关闭也会遇到重复建连 | 开关对照已复现；该缺陷位于共用独立 ASR 恢复流程。关键任务身份检查及建连入口在当前 HEAD 中已存在，不是本轮诊断新增的逻辑；未据此推断其最早引入版本。 |
| 用户现场那一次一定是上述原因 | **未证实，禁止如此表述。** 旧日志缺少连接尝试、候选关闭、缓冲淘汰和实际发送的同一输入关联证据。 |
| ASR／TTS 本身无问题、所有路径均已验收 | **未证实。** 探针没有真实服务端识别或 TTS；manual／SmartTurn 和 native 不由 Qwen provider 路径的结果代替验收。 |

#### 修复必须遵守的边界

1. **共用建连任务。** 同一输入／路由身份下，预热、PCM 入队和恢复请求应加入同一个建连操作；正常成功只采纳一个候选。显式重试允许新候选，必须有既定失败依据和次数上限。关闭、撤销及换身份要使旧操作失效；取消一个普通等待者不能误伤仍由当前会话拥有的共享操作。
2. **保住已接受首句。** 尚在等待本人验证的滚动候选缓存，与已确认并交给 ASR 等待发送的音频，具有不同的淘汰约束。不能把通用环形缓冲全改成保留开头，也不能让后续静音覆盖已经接受的首句后仍报告交付成功。候选尚未确认时的现有滚动缓存行为须有对照用例保留。
3. **容量和等待必须有界。** 保留现有容量约束，不通过无限扩容解决；持续说话、连续多句或连接失败导致无法完整保留时，须给出明确的背压／交付失败结果及一致的恢复状态，不能静默丢头、拼接残句或等下一句话偶然恢复。ASR 单次 ready 等待现为 10 秒；正常热切换的 5 秒预算不能未经论证直接套给冷连接。
4. **保留结束一句话所需的信息。** 不可简单删除全部静音，尤其不可删除句中停顿来压缩时间线。Qwen provider 当前使用 server VAD，配置没有显式固定句尾静音时长；若压缩连续句尾静音，必须先定义并验证结束边界和保留规则。不得为 provider 模式随意补 manual commit。无法安全压缩时按有界失败处理。
5. **区分资格和交付。** ACTIVE 表示本人已获语音资格，不要求改成等待 ASR 出字才激活；但它不能替代“首句交付成功”。至少区分本地接收／缓冲、实际写出、Provider 事件和转写结果。错误、淘汰和超时要可关联到本次输入；诊断只记身份、序号、字节数、时长和原因，不落原始语音或原始对话。
6. **不重复、不越权。** 只能对确定未发送且仍获授权的音频继续交付；已写出或结果不明的部分不能整句重投。停麦、换角色／档案、权限撤销、路由接管后禁止恢复旧资格或将旧音频交给新身份。保留原始采集时间及 30 秒闲置规则，连接等待、重试和补发不能重新计时。
7. **限制改动范围。** 优先在独立 ASR 的建连协调、待连接交付和必要的中立结果契约中修复；不调整声纹模型、阈值、1.5／3 秒检查点、10 次输入归档及独立 TTS 清理竞态。共用模块发生修改时，仍须验证 manual／SmartTurn、provider 路径和 native 隔离，不把本次证据外推到所有 Provider。

影响分析：`_runtime_identity_matches` 为 **HIGH**（15 个直接调用方、41 个受影响符号，涉及提交、终态、错误、关闭和状态通知），禁止以删除通用身份校验作为快捷修复。`_ensure_transport_restart_task` 的图谱结果为 LOW（3 个直接调用方、7 个受影响符号），仍须核对恢复／候选拒绝路径。`_handle_transport_prewarm_event` 为 LOW（1 个直接调用方）。图谱对生命周期 `accept_audio` 没有给出上游调用，但源码明确存在 `IndependentAsrRuntime.submit → lifecycle.accept_audio`，因此不把该 LOW／0 结果当作完整影响证据。

#### 修复前后的验收要求

- 同一身份的预热与 PCM 请求重叠，只产生一次正常成功连接；关闭或换身份时旧连接不能被采纳，取消与重试不会留孤立任务。
- 本人首句、持续静音、再说第二句：分别覆盖已有连接、慢连接、重复请求及重试；核对两句的实际 PCM 顺序、首尾和次数，不能只断言状态或队列为空。
- 容量临界点、真正超过容量的长语音、连续多句及长时间静音：已接受输入完整交付或得到明确失败，不能静默淘汰后伪装成功；内存和任务数量保持有界。
- 真实 Qwen provider 还须确认句尾能触发正常 endpoint／final；本地模拟接收端通过不代替此项。保留 Web／Electron 开发态实测要求，不要求安装包。
- 保留停麦、撤权、换路由、30 秒到期、部分写入失败、结果不明、迟到回调及正常热切换的自动回归；保护首句不能恢复旧权限、重放已发送音频或延长激活资格。

**本节分析结论已由源码与因果对照支持；生产修复、现场原因归因及实机验收仍未完成。** 后续实施应把探针变成可重复的正式回归，并在实际发送层补齐诊断证据，再判断是否解决用户现场问题。

### 15.16 待机首句丢失：详细修复方案与约束边界

本节是待实施方案。基线为当前 `codex/voice-session-activation` 工作区，保留已有降噪、候选容量、连接交接和诊断改动；不新建分支／工作树，不顺带提交、推送、重启或修复独立 TTS 清理竞态。依据为 15.14—15.15 的源码与隔离复现；不把它表述为用户现场那次的唯一已知原因。

#### 15.16.1 目标行为与本轮取舍

本人长句通过声纹后，这句话及其原有停顿、句尾静音应按顺序进入独立 ASR。连接正在准备时保留已接受音频，连接就绪后自动继续交付，不要求用户再说一句来推动队列。正常路径只能交付一次。

本轮采用 **共用建连操作 + 不淘汰已接受前缀 + 现有上游队列承接背压**。不做静音剪裁、不人工补静音、不把连续静音压缩成较短音频，也不改 ASR 的断句权威。这样保留完整音频时间线，避免为解决缓存容量引入新的断句参数。

现有两级容量分别保持：

| 已有位置 | 容量 | 修复后的职责 |
|---|---|---|
| 独立 ASR 待连接缓存 | 256,000 字节，16 kHz 单声道 PCM16 约 8 秒 | 一旦接收需完整保留的前缀，按 FIFO 保存，不能被后续静音覆盖 |
| 声纹输出队列 | 256,000 字节，约 8 秒，包含已领取但未完成的帧 | ASR 暂时无空间时保留尚未交出去的后续音频，暂停发送者，不暂停本地采音和资格计时 |

不再增加第三个同等大小的 PCM 缓存。两级额度合计约 16 秒指这两处的逻辑排队容量，不代表进程总内存、保证等待时长或新增配置上限；实际还受进入队列时已有数据、单帧大小、候选引用和其他既有队列影响。不得在提交重试时额外复制整句，内存核算须包含在途帧和瞬时所有权交接。

对于已复现的约 2.52 秒首句：5 秒单次连接应只建连一次并完整交付；9 秒单次连接应在 ASR 达到容量时把后续音频留在上游，连接就绪后仍完整交付。这两项是必过行为，不可用“提前报错”替代。真正超过可用总容量或连接失败的情况，明确报告本次交付失败，不静默丢头后继续假装成功。

#### 15.16.2 连接操作：所有入口共享一位所有者

复核并统一 `_handle_transport_prewarm_event`、`_handle_detector_prewarm_event`、`_ensure_continuous_provider_wake`、PCM `submit`、候选拒绝后的恢复等所有建连入口。将 `_restart_transport` 的连接执行部分作为单一内部 worker，入口只请求或等待同一个受管理任务，不再一边直接建连、一边另建任务占位。

1. 在无 `await` 的小段中检查当前操作并安装新操作对象／task 引用，之后才启动实际连接。操作记录输入身份、Provider selection、factory、创建时间、固定截止时间和 task；不以任务名判断归属。
2. 相同身份的请求返回现有操作；调用方可以等待，也可以只触发预热。普通等待使用 shield，取消一个等待者不自动取消仍属于会话的共享连接。
3. 实际连接成功后，重新核对输入、路由、权限、操作对象和 factory／selection，只采纳一个候选。迟到旧候选仅清理自身，不改新操作或新 session。
4. 错误按现有 Provider policy 的最大尝试数和退避处理。新音频、第二个等待者和重试不能重新起算操作截止时间，也不能无限追加尝试。
5. 停麦、关闭、换路由／Provider、换输入所有者等权威撤销先使操作失效并唤醒等待者，再取消、退休候选和有界收尾。普通等待者取消与权威撤销必须走不同分支。

单次 ready 等待继续受现有 10 秒上限约束；总 ready／退避预算固定为 `N × 10 秒 + 原 policy 的 N−1 次退避之和`，其中 N 为当前 policy 最大尝试数，不另加重试。候选清理另设每次最多 2 秒的协调等待；超时后候选保持失效并由已有资源管理路径跟踪、关闭底层资源，不能把无法终止的旧 worker 当成已回收并继续无限建新 worker。若无法确保资源数量有界，本次操作失败，不继续重试。以上是冷连接预算，不改正常热切换的 5 秒合同。

保留通用 `_runtime_identity_matches` 的全部隔离职责。通过稳定安装共享任务和专属操作票据解决假过期，不直接删掉 `transport_task` 检查，也不放宽其他调用方的身份判定。operation 完成／清理使用对象相等的 CAS，防止旧 finally 清掉新任务引用。

#### 15.16.3 待发送前缀：所有权与保护起点

通用 `AudioRingBuffer` 继续用于尚未确认的滚动观察窗口，不全局改变其“保留最新数据”的语义。在独立 ASR 生命周期内增加待发送前缀的受保护模式，容量沿用现有 `_pending_connect` 额度；实现可使用有界 FIFO 或该缓存的无淘汰追加操作，不平行维护另一份完整音频。

- 声纹路径：首次授权回放进入 Core 时，桥接一个中立的“此批未发送前缀须完整保留”描述符，包含逻辑输入身份、批次／起始序号；ASR 不依赖声纹模型或录制服务。保护从第一帧（含前滚）开始，不能等 8 秒缓存已经淘汰后才打开。
- 后续 LIVE 帧若跟在同一待连接前缀之后，继续受相同 FIFO 顺序和容量约束；REPLAYING 变 ACTIVE 不能清除下游保护。描述符必须在帧实际提交前可用，不能依赖可能迟到的 UI 状态回调。
- 普通独立 ASR 路径：未确认候选保持现有前滚策略；一旦本地语音已确认且等待连接，应同样保护已接受的待发送前缀。不能因为声纹关闭就允许确认过的输入被静默覆盖。
- 保护只保证数据保存和有序交付，不绕过现有 ASR endpointing 可用性及人声确认条件。若模型／检测器无法确认或不可用，应明确失败，不强行打开 ASR 回合。
- 连接被当前操作采纳、ASR 回合满足可发送条件且前缀已按序转交发送队列后，释放对应待连接额度。缓存保护结束不等于远端识别已完成。

一帧的逻辑所有权只能处于：上游待发送／本次在途领取 → ASR 已接收的前缀 → 有界发送队列／worker → 实际写出。交接期间可引用同一不可变 bytes，但不能两边都认为有权重投。`drain_active_start_audio` 之类的取出操作必须与下游成功接收配对；下游队列拒收时保持原所有权或明确终止本次交付，不能先清空再忽略失败。

#### 15.16.4 背压：暂停发送，保留完整时间线

优先让独立 ASR `submit` 在“受保护前缀无空间、且当前建连／准备操作仍能释放空间”时等待容量，不立即返回 ACCEPTED，不让调用方反复盲投。这能直接复用声纹现有单发送者和输出 lease：等待期间该帧仍留在声纹输出额度内，后续采音进入剩余输出队列。

容量等待须遵守以下顺序：

1. 用输入身份和容量版本尝试预留整帧空间；满时先订阅通知再复查条件，避免“刚释放空间却错过通知”。单帧大于总容量直接明确拒绝。
2. 等待不得持有 runtime、controller、detector、final 或 session-swap 锁，否则会阻塞建连提交和缓冲排空。使用容量事件／Condition，禁止高频轮询、每帧新建等待任务或无期限 sleep。
3. 在会产生重复副作用的检测、帧序号累计及入队前完成容量预留。唤醒后只处理一次；若必须先处理检测，则必须保存这次处理结果及 reservation，不能重跑同一帧的检测或回合事件。
4. 连接就绪后，先将已接受前缀交给当前发送队列，再唤醒容量等待者；先发旧 PCM、后接新 PCM。不能用“session ready”本身作为允许绕过旧数据的依据。
5. 停麦、换身份、失败、容量溢出、关闭和超时都要唤醒等待者并返回确定结果；正常热切换仍受原交接屏障约束，容量通知不能绕过该屏障。
6. 等待截止不晚于拥有该前缀的操作截止。若没有仍能推进的准备／建连操作，例如连接已就绪但检测不能确认、额度又满了，明确失败，不能无限等一个不会到来的容量通知。

声纹启用时，ASR 等待不会阻塞本地资格计时；真正的人声按原始采集时间更新 30 秒期限。声纹关闭时，同一 `submit` 等待会反压现有普通输入消费者，因此必须单独覆盖原始输入队列满、停麦、路由接管和消费者取消，不能给这一路返回“稍后重试”后把当前帧直接丢掉。

本轮不删除静音，因此不新增 Qwen server VAD 参数、不切换 manual commit、不改句中停顿及 Provider 音频样本时间线。若实施发现既有队列无法承接 9 秒对照用例，应先修正所有权或背压连接，不能临时改成裁剪静音、扩大容量或把该用例降为允许失败。

#### 15.16.5 交付结果与失败闭合

将“本地移交”与“实际写出”分别表达：

| 结果 | 所有权与后续动作 |
|---|---|
| 等待容量 | submit 尚未结束；上游保留帧，不算下游接受，更不算写出 |
| 下游已接收 | ASR 保证已取得当前帧及其有界保存责任；上游可以完成 lease，不再重投 |
| 实际写出 | 由实际网络发送边界产生诊断；仅 adapter 入队不算 WebSocket 已写 |
| Provider 事件／转写 | 分别记录服务端输入事件、endpoint／final 和本次转写交付；不把写 socket 成功等同识别成功 |
| 未发送且失败／撤销 | 终止本次输入所属的等待与缓冲，走明确失败／现有恢复流程 |
| 部分写出或结果不明 | 退休不安全会话，禁止整句自动重投，不向继任会话盲目补发 |

建议在中立提交结果中增加明确的本地接收阶段，并在 `OutputCommit` 中增加相应的本地移交结果。controller 可在成功移交下游所有权后释放 lease，但日志要叫“本地回放已移交”，不能继续将它描述为远端传输完成。新增枚举要逐个核对所有判断与序列化位置，不能依靠当前 `complete_output` 的非失败兜底分支把任意新值当成功；旧测试替身的默认结果也不能冒充 wire 证据。

若声纹输出队列溢出或运行时主动结束了本次交付，Core 必须同步撤销同批 ASR 前缀与连接等待，不能仅把上游设 UNAVAILABLE、任由下游稍后发送残留的半句话。若下游已经部分写出，按不确定交付路径关闭，不能承诺撤回远端已接收内容。未启用声纹的路径也要有明确的失败及队列清理结果。

ACTIVE 仍表示语音资格；待发送、发送失败独立提示。失败不因“连接后来好了”自行消失，也不复活已撤销资格。真实传输错误沿用当前路由恢复策略；正常等待不得要求重新录声纹或重新加载健康模型。

建议使用两个用户可读状态：等待明显超过约 1 秒时显示“正在连接语音服务，这句话会在连接后继续发送”；确定失败时显示“这句话没能发送成功，请稍后重说”。后者不用于尚在正常等待的情形。若发生部分交付／结果不明，应改为“这句话的处理结果未确认，请稍后查看回复”，避免鼓励自动重复输入。复用现有状态通知通道，并同步全部 8 个 locale；不在界面暴露线程、缓冲或模型实现术语。

#### 15.16.6 可观测性与隐私

为每批输入关联 `ingress/activation generation`、交付批次、connect operation、候选连接、原始序号区间。记录：开始／加入连接、成功采纳／迟到关闭及原因、重试、两级队列字节与高水位、容量等待／恢复、被拒收／淘汰的明确原因、送入 worker 的字节、实际 WebSocket 写出字节，以及 Provider endpoint／final 与转写是否交付。

正常路径按批次和阶段汇总，不逐 10 ms 帧刷 INFO。连接对象地址只能辅助定位，不能充当可复用批次身份。实际 socket 计数要放在真实 worker 的发送 await 边界并带对应代次；失败或取消跨越该 await 时不得记成确定未发送。无需把每帧网络 ACK 回传声纹状态机，也不能伪造 Provider 未提供的确认。

不记录原始 PCM、声纹向量、完整文本、密钥或音频 base64。验收中的标记 PCM 使用生成样本；已有用户录音仅在本地隔离实验使用，不把它提交仓库或额外上传。

#### 15.16.8 实施顺序和必过用例

1. **先固化反例。** 把当前本地录音探针改成可重复的生成 PCM／明确检测事件测试；使用事件屏障控制连接时序，避免依赖真实 sleep 才复现。分别证明旧逻辑发生重复建连、前缀淘汰，以及单次慢连接仍会丢前缀。
2. **统一建连所有权。** 先实现共用操作与撤销／预算，不改缓冲；证明同一身份一次正常连接，取消与迟到候选不污染继任者。单独验证慢连接容量反例仍能失败，避免错误宣布全部修复。
3. **接入保护和背压。** 实现两级既有队列的有界交付、原子排空及失败闭合，同时接入声纹和普通输入调用方；不能只修改 lifecycle 的返回值而遗漏上游持帧。
4. **补齐结果和诊断。** 更正本地接受／wire 语义，接入用户状态和所有语言；运行相关静态检查。
5. **跑完整相关回归，再做开发态实测。** 复用已有声纹档案，覆盖 Web 和 Electron，不要求打安装包。

| 验收场景 | 必须证明的结果 |
|---|---|
| 已有 ready 连接；本人长句激活 | 首句包含前滚、开头、结尾，顺序正确，模型只收到一次对应输入 |

| 等待期间继续说第二句 | 在容量允许范围内按原顺序交付，不跳过第一句、不把两句前后颠倒；远端是否分句按原协议验收 |
| 8 秒边界、跨边界帧、上游也满、超大单帧 | 每帧原子接收或明确拒绝；没有部分截断后仍返回成功，没有无限缓存 |
| 无法建立连接、重试耗尽、容量不足 | 当前批次明确失败；等待者都能退出，下游不会稍后偷发残留首句 |
| 等空间时停麦／撤权／换角色／换路由 | 旧资格、旧批次和旧连接均不能复活；新输入不被旧清理影响 |
| 连接就绪与等待通知交错 | 无丢唤醒、无锁死；旧队列先移交，新帧才进入发送顺序 |
| 发送部分字节后报错／取消 | 不整句重放；计数与不确定结果一致，迟到回调不能进新回合 |
| 正常热切换恰逢容量等待 | 遵守原 5 秒交接合同、原 idle deadline 和原权限检查，不死锁或重复交付 |
| 本地安静满 30 秒 | 按原始人声采集时间回待机；缓存等待和补发不能重新起算资格 |
| 关闭声纹的普通独立 ASR | 保留原始输入队列有界性、语音唤醒和取消行为，不吞掉等待中的当前帧 |
| manual／SmartTurn 与 native | 共用改动不改变各自 endpointing 权威；native 不被错误套入独立 ASR 的前缀缓存策略 |
| 多次启动、失败、正常切换、停止 | 任务、连接、模型进程和容量等待者没有持续增长；旧资源最终回收或被明确跟踪为异常 |

实际网络验收必须追到 Qwen endpoint／final、转写交付和响应次数；模拟接收端完整不等于云端识别成功。用例失败时按证据分层定位，不直接再次调声纹阈值。

必要检查以仓库当前脚本为准：相关 Core／ASR／声纹／连接恢复正式测试，Core contracts、async blocking、module layering、改动文件 lint 和 `git diff --check`。新增的空间等待、所有权转交和取消路径用变异反证验证：故意恢复重复建连、旧数据淘汰、提前释放 lease、丢通知或绕过撤权时，对应测试必须失败。只有用户另行要求提交时才执行提交／推送流程，提交前需 `gitnexus_detect_changes` 核对范围。

**完成标准：两个缺陷均被修复，5 秒和 9 秒整句对照必过，超出容量的失败可见且闭合，相关路径回归通过，Web／Electron 开发态有整句真实识别证据。** 不以“只剩一次连接”“ACTIVE”“本地回放完成”或测试数量代替这组完成条件。

- 手动断句的检测入口采用有界容量等待，避免授权回放突发塞满既有检测队列；不等待完整 SmartTurn 推理，不扩大检测缓存。重置／关闭使旧等待者退出。
- Soniox 的受保护输入在实际尝试发送后禁止自动整段重投；普通输入保留原 `provider_managed` 策略。新增真实 worker／适配器与模拟 socket 对照测试。
