## 实际处理链

真实文字输入和已发布的文字回复通过现有 conversation-turn 分发器提供可选身份元数据。旧消费者仍使用原接口；合成回放和语音不进入新画像。接受新用户消息后撤销旧候选，待相应上下文理解完成才恢复。

唯一的服务实例由 main-server 组装层创建。每猫娘后台批次最多缓存 24 条事件，每次处理有限截止点，推荐模块全局最多两个并行 summary 模型任务。去重使用真实会话/输入身份，重复投递不会作为新的独立兴趣证据。输入输出总量、模型调用、重试和停机均有边界。

候选理解、反馈、实际采用及拒绝判断使用现有 `summary` 模型配置（model/base_url/api_key）；最终选题与话术使用原主动搭话 `conversation` 模型。没有硬编码新的供应商。模型根据上下文判断 engaged/disengaged/unknown，之后可以修正；沉默保持 unknown，局部拒绝不能扩大成整个兴趣的拒绝。

记忆只通过原有 `/query_memory/{猫娘名}` 读取。PC 私聊由组装层显式授权，沿用当前猫娘的私聊范围；未知或显式空主体范围不会退回私聊。记忆内容仅作上下文，不把读取时间冒充事件发生时间，不修改记忆服务的写入、提取或归档。

当前候选只在既有主动搭话节奏中参与选题。推荐不新建计时器或开口预算；其他来源继续共存。唯一候选被主模型放弃且无其他有效来源或待续话题时直接跳过。模型输出的内部 REC 标记在进入显示、TTS、历史及反馈记录前剥离；正文未真正采用候选，也不会登记「已聊」。

已聊记录在服务器真实写入同步消息队列时捕获，随后异步落盘。它表示 `server_committed`，不声称用户已经看见。TTS 排队、状态切换和 Focus 等待后的最终发布均重查开关、角色绑定、根代次、epoch、revision 及用户证据水位。

## 存储与数据边界

文件位置为当前已选定且有效的运行根下 `state/recommendation/<character_id>/state.json`，不是显示名目录。重命名保留归属，删除猫娘后旧任务不能复活数据。文件有 schema/大小/容量校验、CAS、原子替换及跨进程写者锁；取消 HTTP 等待不会把仍在工作的物理写者交给第二个写者。

重置和恢复使用真实 `character_id`、`expected_epoch`、`request_id`、`expected_reset_generation` 和 `expected_confirmation`，最后一项来自状态响应的 `reset_confirmation`。确认绑定画像版本、用户输入及发布边界，慢校验或写入期间有新数据时返回冲突并要求重新确认；恢复自身保存已接受的发布记录可以推进 revision，但不能纳入新增输入。同一运行代次、同一请求内容的不确定重试先匹配原回执，不再次清除后来数据；重启、维护或授权变化使旧确认失效。已落盘但回执失效时，状态查询通过真实回执对齐 epoch/revision，不要求新增聊天，也不重放删除。损坏或未知状态不覆盖为默认空画像，不把未知数量显示成零。重置与删除也清理属于该角色的崩溃临时副本，清理失败不能报成功。

非破坏性恢复使用同一事务协议的 `/recommendation/recover` 入口：新 epoch 中保留既有画像及限制，候选增加持久化 `context_confirmed=false`，只有完整新用户依据参与合并才重新确认。历史文件没有该字段时仍兼容；恢复与清空的回执分别绑定操作模式，不能用同一请求 ID 跨模式重放。

迁移只新增 `state/recommendation` 的明确条目，复用既有复制证据和保留根清理规则，V1 历史条目不改写。存储选择、重启和云存档导入维护阶段提前暂停推荐；重叠维护操作不会互相提前恢复。推荐目录不加入云存档同步。

画像记录仍是用户数据。本机文件不新增加密承诺；发送给模型供应商的内容受现有 summary/conversation 配置及其服务条件约束。新模块不记录原始对话、完整画像、密钥或候选正文到产品日志；状态接口只提供数量和可用性。
